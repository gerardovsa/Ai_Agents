# Sub-Tab Architecture - Technical Guide

**Created:** November 3, 2025  
**Purpose:** Technical specification for implementing sub-tab navigation in external modules  
**Status:** Production Standard

---

## Overview

External modules in the Business AI Platform use a sub-tab architecture to organize related functionality into separate, switchable views. This document outlines the complete structure, implementation patterns, and critical gotchas.

---

## Architecture Components

### 1. Manifest Configuration (`manifest.json`)

Every module with sub-tabs MUST define them in the manifest:

```json
{
    "id": "my-module",
    "name": "My Module",
    "icon": "fas fa-cube",
    "tabs": [
        {
            "id": "tab-one",
            "name": "First Tab",
            "icon": "fas fa-home",
            "description": "First tab description",
            "default": true
        },
        {
            "id": "tab-two",
            "name": "Second Tab",
            "icon": "fas fa-chart-line",
            "description": "Second tab description"
        }
    ]
}
```

**Key Fields:**
- `tabs`: Array of sub-tab definitions
- `id`: Unique identifier (kebab-case, used in DOM)
- `name`: Display name shown in navigation
- `icon`: Font Awesome icon class
- `description`: Optional tooltip/description
- `default`: Boolean (only ONE tab should have this set to `true`)

## 4. Module Implementation Pattern

### Module Class Structure

```javascript
class MyModule extends BaseModule {
    constructor(moduleId) {
        super(moduleId);
        this.backendUrl = 'http://localhost:5001';
    }

    /**
     * Called after BaseModule creates the structure
     * Initialize all sub-tabs here
     */
    initializeSubTabs() {
        console.log('📋 Initializing sub-tabs for MyModule');

        // Initialize each sub-tab
        this.initializeTabOneTab();
        this.initializeTabTwoTab();
    }

    /**
     * Initialize first sub-tab
     */
    initializeTabOneTab() {
        const tab = this.getSubTabContainer('tab-one');
        if (!tab) {
            console.error('❌ Tab container not found: tab-one');
            return;
        }

        // Populate the tab content
        tab.innerHTML = `
            <div class="module-dashboard">
                <h3>First Tab Content</h3>
                <p>Your UI goes here...</p>
            </div>
        `;

        // Load initial data
        this.loadTabOneData();
    }

    /**
     * Initialize second sub-tab
     */
    initializeTabTwoTab() {
        const tab = this.getSubTabContainer('tab-two');
        if (!tab) {
            console.error('❌ Tab container not found: tab-two');
            return;
        }

        tab.innerHTML = `
            <div class="module-dashboard">
                <h3>Second Tab Content</h3>
                <p>Your UI goes here...</p>
            </div>
        `;

        // Load initial data
        this.loadTabTwoData();
    }

    /**
     * CRITICAL: Correct implementation of getSubTabContainer
     * Must target .module-subtab-content specifically
     */
    getSubTabContainer(tabName) {
        return document.querySelector(`.module-subtab-content[data-subtab="${tabName}"]`);
    }

    /**
     * Optional: Handle sub-tab activation
     * Called by BaseModule when user switches tabs
     */
    onSubTabActivate(subTabId) {
        console.log(`🔄 Sub-tab activated: ${subTabId}`);
        
        // Refresh data when tab becomes active
        if (subTabId === 'tab-one') {
            this.loadTabOneData();
        } else if (subTabId === 'tab-two') {
            this.loadTabTwoData();
        }
    }

    // Data loading methods
    async loadTabOneData() {
        // Implementation...
    }

    async loadTabTwoData() {
        // Implementation...
    }
}
```

## 5. Critical Implementation Rules

### ✅ DO:

1. **Use `.module-subtab-content` selector in `getSubTabContainer()`**
   ```javascript
   getSubTabContainer(tabName) {
       return document.querySelector(`.module-subtab-content[data-subtab="${tabName}"]`);
   }
   ```

2. **Initialize ALL sub-tabs in `initializeSubTabs()`**
   - Even if a tab is not active, populate its content
   - This ensures instant switching without loading delays

3. **Check if container exists before populating**
   ```javascript
   const tab = this.getSubTabContainer('tab-name');
   if (!tab) {
       console.error('❌ Tab container not found: tab-name');
       return;
   }
   ```

4. **Use semantic tab IDs in kebab-case**
   - ✅ `invoice-processing`
   - ✅ `usage-analytics`
   - ❌ `invoiceProcessing`
   - ❌ `invoice_processing`

5. **Set ONE default tab in manifest**
   ```json
   {
       "id": "main-tab",
       "name": "Main Tab",
       "default": true
   }
   ```

### ❌ DON'T:

1. **DON'T use generic `[data-subtab]` selector**
   ```javascript
   // WRONG - This matches buttons AND content divs!
   return document.querySelector(`[data-subtab="${tabName}"]`);
   ```

2. **DON'T override `.module-subtab-content` display in module CSS**
   ```css
   /* WRONG - This breaks tab hiding! */
   .module-subtab-content {
       display: block !important;
   }
   ```

3. **DON'T manually manage the `.active` class**
   - BaseModule handles this automatically
   - Trust the framework's `switchSubTab()` method

4. **DON'T wrap everything in a `dashboard-card`**
   ```html
   <!-- WRONG - This breaks layout! -->
   <div class="dashboard-card">
       <div class="card-header">...</div>
       <div class="stats-grid">...</div>
   </div>
   
   <!-- CORRECT - Card header is separate from content -->
   <div class="module-dashboard">
       <div class="stats-grid">...</div>
   </div>
   ```

5. **DON'T create multiple tabs with `default: true`**
   - Only ONE tab should be marked as default
   - If multiple are marked, the first one wins

## 6. Tab Switching Flow

### User Clicks Tab Button

```
User clicks button
    ↓
BaseModule.switchSubTab(subTabId) is called
    ↓
1. Remove .active from ALL .module-subtab-content divs
2. Remove .active from ALL .module-subtab-btn buttons
    ↓
3. Add .active to target .module-subtab-content
4. Add .active to target .module-subtab-btn
    ↓
5. Call module.onSubTabActivate(subTabId)
    ↓
Module can refresh data or update UI
```

### CSS Applies Display Logic

```
.module-subtab-content (no .active)
    → display: none
    → Tab is HIDDEN

.module-subtab-content.active
    → display: block
    → Tab is VISIBLE
```

## 7. Common Gotchas and Solutions

### Gotcha #1: All Tabs Showing at Once

**Symptom:** All sub-tab content appears simultaneously, stacked vertically

**Cause:** `getSubTabContainer()` is selecting the wrong element (usually the button instead of the content div)

**Solution:**
```javascript
// CORRECT:
getSubTabContainer(tabName) {
    return document.querySelector(`.module-subtab-content[data-subtab="${tabName}"]`);
}
```

---

### Gotcha #2: Layout Chaos with Misplaced Elements

**Symptom:** Stats cards, buttons, and content are scattered everywhere

**Cause:** HTML structure has extra wrapper divs that conflict with CSS grid/flexbox

**Solution:** Keep structure flat inside `.module-dashboard`
```html
<div class="module-dashboard">
    <!-- Summary Cards -->
    <div class="stats-grid">...</div>
    
    <!-- Controls -->
    <div class="dashboard-controls">...</div>
    
    <!-- Table -->
    <div class="table-container">...</div>
</div>
```

---

### Gotcha #3: Tab Content Not Loading

**Symptom:** Clicking a tab shows empty content or loading spinner forever

**Cause:** 
- Tab initialization method not called in `initializeSubTabs()`
- API call failing silently
- Backend not running

**Solution:**
1. Check `initializeSubTabs()` calls all init methods
2. Add error handling to data loading methods
3. Verify backend is running on `localhost:5001`

---

### Gotcha #4: Tab Switching Not Working

**Symptom:** Clicking tab buttons does nothing

**Cause:**
- Event listeners not attached (BaseModule should do this)
- JavaScript error preventing execution

**Solution:**
1. Open browser DevTools → Console
2. Look for errors when clicking tabs
3. Check if `BaseModule.switchSubTab()` is being called

### Module Implementation

```javascript
class StockManagementModule extends BaseModule {
    constructor(moduleId) {
        super(moduleId);
        this.backendUrl = 'http://localhost:5001';
    }

    initializeSubTabs() {
        console.log('📋 Initializing Stock Management sub-tabs...');

        // Initialize all 6 tabs
        this.initializeInvoiceProcessingTab();
        this.initializeUsageAnalyticsTab();
        this.initializeReorderDashboardTab();
        this.initializeProfitAnalysisTab();
        this.initializeSQLViewerTab();
        this.initializeAIAnalyticsTab();
    }

    initializeReorderDashboardTab() {
        const tab = this.getSubTabContainer('reorder-dashboard');
        if (!tab) return;

        tab.innerHTML = `
            <div class="module-dashboard">
                <!-- Summary Cards -->
                <div class="stats-grid">
                    <div class="stat-card critical">
                        <div class="stat-icon"><i class="fas fa-exclamation-triangle"></i></div>
                        <div class="stat-content">
                            <div class="stat-label">Critical Stock</div>
                            <div class="stat-value" id="reorder-critical-count">--</div>
                        </div>
                    </div>
                    <!-- More stat cards... -->
                </div>

                <!-- Reorder Table -->
                <div class="table-container">
                    <table class="data-table" id="reorder-table">
                        <thead>
                            <tr>
                                <th>#</th>
                                <th>Stock ID</th>
                                <th>Status</th>
                            </tr>
                        </thead>
                        <tbody id="reorder-table-body">
                            <tr>
                                <td colspan="3" class="loading-cell">
                                    <i class="fas fa-spinner fa-spin"></i> Loading...
                                </td>
                            </tr>
                        </tbody>
                    </table>
                </div>
            </div>
        `;

        // Load data
        this.loadReorderDashboard();
    }

    async loadReorderDashboard() {
        try {
            const response = await fetch(
                `${this.backendUrl}/api/stock/list-unified?is_active=true`
            );

            if (!response.ok) {
                throw new Error(`HTTP ${response.status}`);
            }

            const result = await response.json();
            
            if (!result.success) {
                throw new Error(result.message);
            }

            // Populate table with data
            this.populateReorderTable(result.data.stocks || []);

        } catch (error) {
            console.error('Failed to load reorder data:', error);
            // Show error in UI
        }
    }

    getSubTabContainer(tabName) {
        return document.querySelector(`.module-subtab-content[data-subtab="${tabName}"]`);
    }

    onSubTabActivate(subTabId) {
        console.log(`🔄 Activated: ${subTabId}`);
        
        // Refresh data when tab becomes active
        if (subTabId === 'reorder-dashboard') {
            this.loadReorderDashboard();
        }
    }
}
```

## 9. Testing Checklist

When implementing sub-tabs, verify:

- [ ] Manifest has `tabs` array with valid tab definitions
- [ ] One tab marked with `"default": true`
- [ ] Tab IDs use kebab-case (no underscores or camelCase)
- [ ] `initializeSubTabs()` calls all init methods
- [ ] Each init method checks if container exists
- [ ] `getSubTabContainer()` uses `.module-subtab-content` selector
- [ ] Only ONE sub-tab visible at a time
- [ ] Clicking tabs switches content correctly
- [ ] Browser console shows no errors
- [ ] Data loads correctly when tab becomes active
- [ ] Layout is clean (no overlapping elements)

## 12. Summary

**The sub-tab system works through:**

1. **Manifest** defines tab structure
2. **BaseModule** auto-generates HTML structure with buttons and content divs
3. **CSS** hides all tabs except `.active` one
4. **Module** populates each tab with content in `initializeXXXTab()` methods
5. **BaseModule** handles switching when buttons clicked
6. **Selector** must use `.module-subtab-content[data-subtab="..."]` to avoid ambiguity

**Most common mistake:** Using generic `[data-subtab]` selector which matches BOTH buttons and content divs, returning the wrong element.

**Quick fix:** Always use `.module-subtab-content[data-subtab="${tabName}"]` in `getSubTabContainer()`.
