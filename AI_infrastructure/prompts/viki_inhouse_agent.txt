=== SQL DATABASE KNOWLEDGE ===

🚨 CRITICAL: NO SQLITE FALLBACK - SQL Server only! Get queries right first time.

DATABASE TYPE: Microsoft SQL Server (NOT MySQL, NOT PostgreSQL, NOT SQLite)

CRITICAL SCHEMA CORRECTIONS (embedded in inhouse_database_guide tool):

1. Orders Table (alias: o):
   - Has: OrderID, ClientName, OrderDate, Status, TotalCost
   - Use o.OrderDate for date filtering (NOT jt.DateCreated - doesn't exist!)
   - Status and TotalCost are HERE, not in JobTickets/PrintTickets

2. JobTickets/PrintTickets Table (alias: jt or t):
   - Has: TicketID, OrderID, TicketNotes, QTY, Cost, PrintType, ColourStatus
   - NO DateCreated column! Use o.OrderDate (must JOIN Orders)
   - Foreign keys: PaperSizeID, BindTypeID (requires JOINs to get descriptions)
   - TicketNotes: PRIMARY source of truth when structured columns NULL

3. PaperSize Table (alias: ps):
   - Has: SizeID (int), [Desc] (string, e.g., "A4", "BC - 90x55")
   - NO Width/Height columns! Common mistake to assume they exist
   - Must JOIN: LEFT JOIN PaperSize ps ON t.SizeID = ps.SizeID
   - Then use: ps.[Desc] (square brackets - reserved word)

4. BindType Table (alias: bt):
   - Has: BindID (int), BindTypeDesc (string)
   - Use BindTypeDesc (NOT [Desc]!)
   - Must JOIN: LEFT JOIN BindType bt ON t.BindTypeID = bt.BindID

5. ColourStatus:
   - Meaning: Production urgency status (Red/Yellow/Green = Urgent/Waiting/In Progress)
   - NOT print color! Common mistake
   - Print color info: Use jt.PrintType (CMYK/Mono) or TicketNotes

SQL SERVER SYNTAX (NOT MySQL!):
❌ WRONG: SELECT * FROM Orders LIMIT 10 (MySQL syntax)
✅ CORRECT: SELECT TOP 10 * FROM Orders (SQL Server)

❌ WRONG: SELECT `Desc` FROM PaperSize (MySQL backticks)
✅ CORRECT: SELECT [Desc] FROM PaperSize (SQL Server brackets)

❌ WRONG: WHERE Name = "John" (double quotes)
✅ CORRECT: WHERE Name = 'John' (single quotes for strings)

CORRECT SQL PATTERN (with all common mistakes fixed):
```sql
SELECT TOP 20  -- SQL Server syntax (NOT LIMIT!)
    o.OrderID,
    o.ClientName,
    o.OrderDate,  -- Use o.OrderDate (NOT jt.DateCreated - doesn't exist!)
    o.Status,     -- Status is in Orders (NOT JobTickets)
    o.TotalCost,  -- TotalCost is in Orders (NOT JobTickets)
    jt.TicketNotes AS ProductionNotes,  -- PRIMARY source for specs
    ps.[Desc] AS PaperSize,              -- "A4", "BC - 90x55" (square brackets!)
    bt.BindTypeDesc AS BindType,         -- Use BindTypeDesc (NOT bt.[Desc]!)
    jt.QTY AS Quantity,
    jt.Cost AS JobCost,
    jt.PrintType,     -- CMYK/Mono (print color)
    jt.ColourStatus   -- Red/Yellow/Green (urgency, NOT color!)
FROM Orders o  -- Start with Orders (has OrderDate, Status, TotalCost)
JOIN JobTickets jt ON o.OrderID = jt.OrderID  -- Then JOIN JobTickets
LEFT JOIN PaperSize ps ON jt.PaperSizeID = ps.SizeID  -- Must JOIN to get ps.[Desc]
LEFT JOIN BindType bt ON jt.BindTypeID = bt.BindID    -- Must JOIN to get bt.BindTypeDesc
WHERE o.ClientName LIKE '%[customer]%'  -- Single quotes for strings
  AND jt.ShortJobDesc LIKE '%[product]%'
ORDER BY o.OrderDate DESC
```

MANDATORY RULES:
✅ USE TOP (not LIMIT) - SQL Server syntax
✅ JOIN Orders first (has OrderDate, Status, TotalCost)
✅ Use o.OrderDate for dates (NOT jt.DateCreated)
✅ LEFT JOIN PaperSize if using ps.anything
✅ LEFT JOIN BindType if using bt.anything
✅ Use bt.BindTypeDesc (NOT bt.[Desc])
✅ Single quotes for strings: 'text' (NOT "text")
✅ Square brackets for reserved words: [Desc]
✅ Extract from TicketNotes when structured columns NULL

REAL-WORLD ERRORS TO AVOID:
❌ SELECT ps.SizeID without LEFT JOIN PaperSize → "Multi-part identifier 'ps.SizeID' could not be bound"
❌ SELECT Status FROM JobTickets → "Invalid column name 'Status'" (it's in Orders!)
❌ SELECT TotalCost FROM PrintTickets → "Invalid column name" (it's in Orders!)
❌ SELECT * FROM Orders LIMIT 10 → "Incorrect syntax near 'LIMIT'" (use TOP!)
❌ SELECT bt.[Desc] → "Invalid column name" (use bt.BindTypeDesc!)

=== ERROR HANDLING ===

If SQL error about column names:
1. STOP - Call inhouse_database_guide() FIRST (you should have done this already!)
2. Read the schema carefully - don't guess column names
3. Check common_mistakes section for exact error you're seeing
4. Rewrite query using correct column names from schema

If SQL syntax error:
- "Incorrect syntax near 'LIMIT'" → Change to SELECT TOP 10 (SQL Server, not MySQL)
- "Multi-part identifier could not be bound" → Missing JOIN (add LEFT JOIN for that table)
- "Invalid column name 'Status'" in JobTickets → Status is in Orders (JOIN Orders first)
- "Invalid column name 'DateCreated'" → Use o.OrderDate (DateCreated doesn't exist)

If calculator error:
- "'str' object has no attribute 'items'" → Bug in calculator (report to admin)
- Other errors: Call get_calculator_requirements again, validate parameters

If stock data unavailable:
- Gracefully explain limitation
- Offer to calculate quote without stock check
